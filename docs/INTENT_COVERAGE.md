# Product intent to backend coverage

2026-09-09. Joe reaffirmed that combining current and past evidence into unexpected,
useful understanding is the point of Personal OS. This is a traceability audit and
acceptance catalogue, not another execution plan. EXECUTION_PLAN owns work order.

## Intended outcome

An ongoing account of Joe's life: observations, calculated measures, revisable event
reconstructions, cross-domain patterns, forecasts and accountable actions. Strength
and body composition remain the primary objective, without deleting the other domains.
“Mega insights” means depth of supported understanding, not a quota of findings or
permission to make unsupported deductions. An honest unresolved event is a result.

## Data availability findings and priorities

Verified locally by Codex: archive manifests cover health, browser/media, transactions,
calendar, location, body composition, reference tables and old derived outputs. The
real Health export contains unsupported types and workout elements. These observations
justify inventory work, not a claim that every source is available in production.

The older concept also names Spotify plays, Google Search, bank exports and other
old-workspace assets. Their present locations/availability have NOT been verified by
this audit. Inventory must locate them or mark unavailable; never manufacture them.
Old summaries and models must be separated from raw source records and duplicate copies.

Prioritize real capture and historical preservation; then training/body/food/recovery
inputs and useful cross-domain context. Record counts alone cannot prioritize value.
Inspect actual fields before promising a derived metric (a workout timestamp is not a
lifting set). Older Health records outside the recovery window need explicit dispositions.

## Completion rule

M6 cannot claim the original product intent is covered until this table is reconciled
with the full requirement ledger, R1-R12 have evidence or an authorized explicit deferral,
and every available source has a disposition. Numerical likelihoods require measured
calibration, not agent self-confidence. More output does not constitute better insight.

Implementation checkpoints: M4 closes reconstruction-local R1-R8/R10/R12 and exposes
lineage/uncertainty contracts; M5 closes R9/R11 with the statistical consumers. All
cases are required by M6. Retrospective event-time ranges do not relax RULE-04's
knowledge-cutoff constraint. Uncalibrated alternatives use explicit ambiguity or
insufficiency wording, not unsupported verbal probability.

Private inventory seed: `_legacy_snapshot/data_capability_inventory_2026-09-09.json`
contains archive table metadata and Health type counts/date ranges. It is gitignored;
source inventory implementation must finish live-use mapping and archive date scans.

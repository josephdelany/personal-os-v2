# ADR-0084 — Original product intent and evidence reconstruction

Date: 2026-09-09. Accepted scope clarification directed by Joe in the current session.
Implementation: OPEN. No migration, dependency or production write authorized here.

## Context

Joe reaffirmed use of all available current/past information, derived measurements,
and detective deductions across sources as the central product purpose. Original
WHAT_THIS_IS, THE_FILE, PLAN_CONVERSATION_LAYER and reasoning §G document broad
cross-source intelligence. Existing B14 encodes several specific links; B19 focuses
on statistical relationships. Their combination had not established a complete
contract for competing event explanations, dependence and retrospective revision.
The prior cleanup organized work but did not prove intent coverage.

## Decision and consequences

Add REQ-REC-001..016, an intent-to-build map with acceptance scenarios, and B14R as
an M4 sub-build. Amend the existing architecture/execution plan rather than create
another master plan. Inventory known history and its analytical uses, explicitly
including unverified assets mentioned in old concepts. Historical labels retire
scheduling claims, not product intent.

This makes multi-source event reconstruction, alternatives, contradictions, dependent
evidence, historical revisions and downstream uncertainty testable release obligations.
It still forbids invented measurements, uncalibrated probabilities presented as confidence,
medical/personality inference prohibited by existing rules, and retrospective confirmation.
Existing integrity rules, evidence tiers, $0/privacy boundaries and Joe's data-definition
questions remain unchanged. No promise of a fixed number of surprising findings is made.

Failure mode: an agent builds only the demonstration cases or inflates insight counts.
Controls: registry-based extensibility, negative/contradictory cases, source-to-capability
inventory, model-unavailable behavior, existing calibration/FDR rules and release coverage.
No numerical scoring scheme is selected by this decision; implementation needs a method ADR.

This clarification increases explicitly tracked work. Earlier percentage/hour estimates
based only on B0-B23 are not authoritative delivery estimates. Continue current capture
and integrity repairs while integrating the missing contracts into their proper owners.

## Review and verification

Independent document review found an M4/M5 dependency cycle and ambiguous RULE-04
handling for retrospective derivations. Fixed: M4 closes local reconstruction cases,
M5 closes downstream R9/R11, all required at M6; the implementation ADR must prove
event/knowledge-window compatibility before late-import derived writes. Also clarified
that unquantified uncertainty cannot bypass probability-language rules. No numbered
constitutional rule or existing requirement was changed. Runtime capability is unbuilt.
